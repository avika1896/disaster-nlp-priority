# An NLP-Based Framework for Actionable Information Extraction and Priority Ranking from Disaster-Related Social Media Posts

B.Tech research project. End-to-end pipeline: disaster social media post →
relevance/actionability → disaster type/location/incident → urgency →
explainable priority score (HIGH/MEDIUM/LOW) → dashboard.

## Dataset

**CrisisMMD v2.0** (annotations-only split, no images needed for this
text pipeline). Already downloaded and processed — the raw TSVs are in
`data/raw/crisismmd_datasplit_all/`, and the processed outputs are in
`data/processed/`. Official source (if you need to re-download):
https://crisisnlp.qcri.org/crisismmd → `crisismmd_datasplit_all.zip`.

### Important, verified data-structure notes (read before touching Step 4+)

1. **Use `label_text`, never `label`.** CrisisMMD's `label` column is
   randomly selected between the text annotation and the image
   annotation (documented in the dataset's own Readme, and verified here:
   it disagrees with `label_text` in ~15–28% of rows). Since this is a
   text-only pipeline, `informative_label` and `humanitarian_category` in
   our processed data are built from `label_text` only.
2. **`damage_severity_image_only` is exactly that — image-only.** CrisisMMD
   never provides a text-based damage label. Don't train a text classifier
   against it as if it were ground truth; it's kept as a weak/auxiliary
   signal, clearly named to prevent misuse.
3. **We do NOT use CrisisMMD's official per-task train/dev/test splits.**
   We verified they aren't tweet-consistent across tasks — 43% of tweets
   land in a different split depending on which task file (humanitarian
   vs. informative) you check. Reusing them naively while merging labels
   into one row per tweet would be incoherent. Instead, `train.csv` /
   `validation.csv` / `test.csv` are our own reproducible (seed=42),
   stratified 70/15/15 split over the deduplicated 16,058-tweet corpus,
   with zero tweet-ID overlap between splits (checked in
   `build_clean_dataset.py`).
4. **`event_holdout_test.csv`** holds out two entire disaster events
   (Sri Lanka floods, Iraq-Iran earthquake) for testing generalization to
   unseen events — separate from the main random split above.

Full details/numbers: `data/processed/step1_exploration_stats.json` and
`data/processed/step2_build_report.json` (both generated by actually
running the scripts, not hand-written).

